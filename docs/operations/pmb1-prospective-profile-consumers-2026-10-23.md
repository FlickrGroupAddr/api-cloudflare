# Prospective PMB-1 source profile selection

Date: 2026-10-23. Source selection under accepted architecture
[ADR0065](https://github.com/FlickrGroupAddr/architecture-design/blob/main/docs/decisions/0065-accept-prospective-integer-accounting-and-no-real-profile.md)
and its [normative profile contract](https://github.com/FlickrGroupAddr/architecture-design/blob/main/docs/prospective-integer-accounting-and-state-profile.md);
implementation and actual qualification remain pending.

The new prospective retained/temporary candidate selects
`pmb1-private-application-no-real-v1`. This applies the already accepted integer
accounting and restricted SQL state domain to new source assembly, its finite
runner, complete qualification packet and independently judged PMB-1 result.
It is an implementation selection, not another owner decision or a successful
qualification claim.

The separately implemented D1 and object readers are the source inputs for this
new path. Historical exact-REAL readers, artifacts, contracts and evidence retain
their original meaning. No old reader is deemed complete, and no historical
snapshot is converted or relabeled to produce equality.

## Explicit consumer context

The retained/temporary assembly must bind the exact source, build, schema,
post-affinity guards, configuration, resources and complete D1/object SQL/KV/alarm
domain. Its finite runner, independent oracle bridge and complete qualification
packet must carry that same profile and candidate context; mixed or absent
contexts refuse. Complete packet preparation follows candidate and operation
interface engineering, rather than substituting a source inventory for them.

For this new profile only, the actual baseline and verdict require absence and
prevention of actual SQL REAL, exact complete admitted typed equality, and every
unamended PMB-1 lifecycle obligation. KV's separate supported finite-number bit
fidelity remains. The visibility boundary remains only the accepted exact-manifest
D1 `main._cf_KV` inaccessible-content exclusion; its observable metadata remains
exact, and object state has no exemption.

The historical composition path retains its original-code fixture and immutable
rollback requirement. A future prospective composition instead needs its own
independently qualified retained baseline and matching immutable rollback target,
with exact profile/source/configuration/schema/resource continuity. This source
selection chooses no existing production artifact or data set, installs nothing,
and permits no rebuilt rollback bytes or historical narrow-test substitution.

## Preserved actual gates

The [PMB-1 contract](prospective-maintenance-contract-decision-2026-10-18.md)
continues to require complete independent source evidence, supported native adapters and full store
population, all writers and alarms, common closed interval, stale-authority
settlement, exact nonforced restoration, ordinary authenticated closed-state
success, cleanup and independent positive judgment. A source
interface, miniature fixture or matching synthetic snapshots cannot supply them.

Actual census, E/R/X transition, treatment of existing REAL balances, current
grants/custody, production target selection, installation, deployment, execution
and reopening retain their separate applicable gates. Existing campaign and
operation ceilings and used allocations remain unchanged. This selection creates
no resource, call, run, capture, credential-renewal or replay allowance.
