# Complete object no-REAL reader source

Date: 2026-10-23. Status: bounded source implementation; managed adapter and
actual namespace qualification remain unpassed.

Authority: architecture [ADR0065](https://github.com/FlickrGroupAddr/architecture-design/blob/main/docs/decisions/0065-accept-prospective-integer-accounting-and-no-real-profile.md)
and its normative [prospective profile contract](https://github.com/FlickrGroupAddr/architecture-design/blob/main/docs/prospective-integer-accounting-and-state-profile.md).
This is the distinct `pmb1-private-application-no-real-v1` object source successor.
The historical exact-REAL oracle and reader requirements retain their meanings.

## Source seam and complete supported scope

`probes/pmb1-no-real-object-reader/reader.ts` exports `capture(source, request)`.
It imports no provider module, registers no Worker/RPC route and supplies no
network, storage, credentials, default adapter or write operation. TypeScript is
required here because the owning object storage runtime and structured KV values
are JavaScript APIs. The small fixture regenerator uses Python.

The caller injects a separately qualified `SupportedSource` with namespace
enumeration, one read session per object, fixed SQL reads, transactional KV list,
exposed alarm time, durable fence observations and closure observations. It must
bound allocation, response bytes, elapsed time and transport before returning
results; reject truncation; execute the exact generated queries; maintain the
full all-writer embargo; and preserve transaction/custody semantics across awaits.
There is no native adapter in this change. This interface does not assert that
an existing provider exposes complete namespace enumeration.

The separately approved request supplies the complete expected object population,
writer identities, closure interval, durable per-object fence bindings, source
artifact bytes with independent expected SHA2-256 pins, guard manifests and
finite limits. Enumeration must match the independent population exactly, in
canonical object-key order, with a final empty page. Source bytes are actually
hashed and checked; the reader source is mandatory. Reviewed pin custody and the
relationship of those bytes to the executing build remain external qualification
requirements. Matching hashes or a caller flag cannot qualify an adapter.

Every object's complete `sqlite_schema`, `pragma_table_list` and every table's
`table_xinfo` are captured and compared with its manifest. The reader rebuilds
the fixed guard definitions from the manifest base census and compares the whole
manifest, including its separately approved canonical hash. Its shape and SQL
definitions match `scripts/private_no_real_guards.py`; the committed synthetic
manifest is generated by that completed implementation and checked by tests.
Actual access probes precede content pages. Observable schema/census is rechecked
before the final fence.

Every included SQL cell is independently decoded from actual `typeof` and fixed
engine `CAST(integer AS TEXT)`/UTF-8-hex/BLOB-hex reads. Canonical signed64 decimal
is validated with `BigInt`; output preserves it as decimal strings, including
signed64 extremes and adjacent values beyond JavaScript Number's exact range.
No delivered SQL Number becomes integer authority. Every actual REAL refuses,
including numerically integral REAL after a guard is bypassed and restored.
Rows retain exact hidden signed64 identities or typed composite WITHOUT ROWID
keys, multiplicity and deterministic ordering. Generated columns are included.

There is no SQL-name omission for `__cf_kv`, `_cf_KV`, bookkeeping or `sqlite_*`.
All exposed transactional KV facts are additionally captured through the KV API.
The D1-only inaccessible `_cf_KV` exception does not apply here. Inaccessible SQL,
unguardable SQLite-owned tables, virtual/shadow storage and ambiguous identities
refuse the entire capture. This source conservatively accepts ASCII SQL metadata
identifiers so its collision handling preserves the completed guard module's
casefold invariants without adding a Unicode casefold implementation. Non-ASCII
SQL identifiers refuse; UTF-8 cell data and non-trigger SQL literals remain
supported. Base-trigger SQL is conservatively ASCII-only as well: the completed
guard implementation's Unicode casefold refusal recognizes spellings such as
long-s in `raiſe ignore`, even inside literals/comments. This reader refuses that
unsupported base-trigger text instead of relaxing the completed guard policy.

## Exact supported KV and alarm representation

KV output uses explicit typed nodes. NULL, boolean, UTF-8 string, signed64 BigInt,
finite Number, full-buffer Uint8Array, ArrayBuffer, dense arrays and plain objects
are supported. Number nodes contain the observed big-endian binary64 bits,
including negative zero. This describes the observed KV API value; only actual
adapter/oracle qualification can establish fidelity to persisted native state.
ArrayBuffer and Uint8Array retain different tags. Arrays retain element order;
object nodes retain every property and insertion order. No JSON coercion or
opaque wrapper substitutes for unsupported native serialization.

Whole-capture refusal covers nonfinite Numbers, out-of-range BigInts, undefined,
invalid text, cycles, shared object/buffer references within a KV value, sparse
arrays, getters, symbols, custom/nonstandard descriptors or prototypes, Date/Map/
Set and other unsupported types, partial byte views, resizable/shared buffers,
depth beyond 16 and aggregate node exhaustion. Bounds apply across all objects.

Alarm ordering binds the existing unregistered `pmb1-object/candidate.ts` source's
`pmb1:alarm-sequence` and structured `pmb1:alarm-invocation` keys. The latter keeps
all three actual fields (`id`, `generation`, `alarmGeneration`) as complete KV
state; the reader additionally checks exact marker shape, canonical sequences,
fence generation and sequence agreement. An absent exposed alarm requires the
invocation key to be absent. A scheduled alarm requires its matching marker.
No new persisted keys, writer protocol or callback RPC is introduced. The native
alarm API time must be an exact nonnegative safe integer millisecond value;
undefined, invalid times or drift refuse. Alarm time is read again before the
final fence. Queued callback identity, delivery provenance and stale callback
disposition remain separately qualified closure requirements.

## Bounds, closure and limits of evidence

Finite limits cover aggregate object/schema/table/column/row/KV/node counts,
serialized traffic/artifact/source bytes, adapter calls, page sizes and elapsed
time, including final artifact encoding. Terminal SQL/KV pages are mandatory.
A deadline refuses further progress;
it cannot cancel an uncooperative native adapter, so external lifecycle and
adapter cancellation/settlement remain mandatory before reusing resources.

Exact closure observations bracket the complete population capture. Their writer
IDs/dispositions must match the independent expected set. Each object's durable
generation, writer epoch, custody and common interval must match its expected
binding, with monotonically ordered observations inside the common closed
interval. The source checks these evidence relationships. It cannot discover an
omitted writer, prove custody, or detect mutate-and-revert through SELECTs alone.
SQL guards do not freeze schema, KV or alarms. Old/direct/operator/provider/CI,
import/restore and queued/alarm writers still require the complete embargo.

Successful results always contain `actualQualification: false`. A lying adapter
can omit a KV key or consistently falsify a source fact; independent complete
oracles and actual managed transport qualification are still required. Synthetic
fixtures prove exercised source mechanisms only. They establish no actual
population/census, barrier, custody, source-bit fidelity, resource continuity,
restoration/reopen, candidate deployment or positive PMB-1 qualification.

## Source verification

Focused Node tests use two complete synthetic SQLite/KV/alarm objects and an
independent direct SQLite-binding oracle with BigInt reads. Coverage includes the
actual existing candidate's structured alarm-marker shape, generated and hidden
identities, composite keys, signed64 extremes/Number neighbors, exact KV types,
omitted stores/population, forged manifests, guard drift, unexpected REAL,
corrupt wire encodings, order/identity drift, adapter faults and aggregate bounds.
The existing candidate fixture's fence is synthetic: that candidate itself cannot
close with a pending alarm. This test proves source shape compatibility only.
