# Finite PMB-1 SOURCE runner

This package supplies inert finite orchestration and **MECHANISM-ONLY** source
rehearsal. It cannot qualify the complete candidate, native storage or a hosted
campaign. There is no provider client, credential loader, action CLI, deployment,
capture, cleanup or automatic reopening path.

The accepted prospective selection is
`pmb1-private-application-no-real-v1` with the separately selected
`pmb1-private-object-kv-interface-v1` boundary. ADR0065, ADR0066 and the existing
[PMB-1 contract](../../docs/operations/prospective-maintenance-baseline-design-2026-10-18.md)
retain their authority. Historical exact-REAL sources and outcomes are unchanged.

## Concrete source programs

`mechanism.make_packet(number)` freezes twelve distinct programs and one selected
SOURCE case. Each test uses a fresh, explicitly synthetic miniature fixture and
external journal. These test fixtures are not additional real campaign slots.
An interruption stops that selected program; the runner does not continue with
another case, repair state or create replacement capacity.

| Case | Concrete reachable SOURCE behavior |
| --- | --- |
| 1 | Guarded write denial; complete baseline/preflight/restored typed equality; temporary/retained synthetic artifact selection |
| 2 | A real SQLite write commits before close; the later admitted-write attempt is denied |
| 3 | Separate denied UPSERT, REPLACE and parent-delete/cascade statements; transaction rollback preserves parent and child |
| 4 | Close commits before the source adapter loses its acknowledgment; durable dispatch remains unknown |
| 5 | Control disappears before comparison; closure readback refuses without normalization |
| 6 | The finite observation lease expires at the observed monotonic clock; the next call cannot dispatch SQL |
| 7 | Both original and temporary delayed writes are attempted separately after exact synthetic retained-target readback and denied |
| 8 | Separate scheduled, session, authentication-failure/audit and quota SQL attempts are denied |
| 9 | Separate service, queue, hint, alarm and binary-KV SQL paths are denied |
| 10 | Trusted direct operator removes a guard; the program fails instead of claiming privilege isolation |
| 11 | Guard removal plus actual mutate-and-revert fails even though final application values match |
| 12 | One declared partial-output interruption retains its partial and receipt in the external journal and stops closed |

Case 12 selects only `partial_output`. Timeout, malformed, truncated, unsupported,
unknown-restore and unknown-cleanup alternatives are **uncovered**; selecting
them refuses preparation. This package does not imply one terminal run can reach
all alternatives. No source program claims native callback retirement, provider
drain, cross-service atomicity, independent separate-store closure, an ordinary
authenticated hosted GET or actual artifact restoration.

The SQLite miniature has eight tables and 29 schema objects. Its object-like KV
and alarm paths are local SQL mechanism examples; they are not Durable Object
typed-KV/alarm qualification. Every setup batch, query, challenge and local fault
appears in the fixed operation list. Setup batches contain at most eight SQL
statements. Each later SQL action has its own invocation and reservation.

## Equality, counters and durable interruption

The reader manifests one query for schema and one for every miniature table,
including empty results. It retains typed NULL/int64/TEXT/BLOB cells, complete
schema and hidden rowids. Actual REAL values refuse. The independent reference
uses the unchanged `pmb1-full-state-oracle` implementation against a separately
initialized closed fixture. That historical oracle still retains its original
REAL semantics; the new consumer refuses REAL before using it.

`runner.SQLiteJournal` uses atomic FULL-synchronous SQLite transactions outside
all compared stores. The immutable campaign latch, exact packet, per-operation
upper-bound reservation and dispatch marker precede effects. Full evidence and
snapshot bytes are retained, not only hashes. Ambiguous reservation, dispatch,
completion or terminal acknowledgments remain spent and unknown. A fresh key,
cold process or terminal result cannot release the singleton reservation.

Declared upper bounds never refund denied/failed work or borrow between cases.
Validation retains 160 requests, 96 reader queries, three captures, 256 SQL
statements and 2,048 effect events per run, plus the independent receipt,
metadata, authenticated-check, mutation, resource, byte and time categories.
Each call has at most eight SQL statements and a deadline bounded by 60 seconds,
the run window and observation freshness. Final source/time checks follow
independent verification and terminal acknowledgment. Journal bookkeeping is
local to this SOURCE model; an actual external service's own requests must be
expanded into the later reviewed operator tree rather than hidden here.

`Oracle` and `Adapter` protocols document the boundary. Arbitrary callbacks,
matching snapshots, `complete=True`, method labels or supplied program digests
cannot claim concrete source completion: the executable source harness accepts
only its exact source-owned program, context, driver and independent reference.
The explicit `after` hook is solely for adversarial SOURCE fault tests.

## Inherited interfaces and the full-candidate refusal

`interfaces.ts` retains the exact inherited SDK types. `native_program.py`
composes twelve immutable, source-owned stage trees, including complete inherited
source pins, exact operator identities, generations, publication, protected
source/owner consumption, terminal/final checks and the private main assessment.
That assessment includes all 134 individual D1 preflight/read queries for the
complete 65-table domain and before/after schema, plus separately bounded journal
pagination. A native logical query has three storage SQL leaves: column discovery,
preacquisition bound and the actual read. Dynamic columns, complete object manifests,
pagination, native RPC wire and actual effects remain explicit refinements; missing
facts refuse. Caller SQL, partial/reordered trees and supplied aggregate counters
cannot fill them. `contracts.verify_attempt` therefore refuses method-label
`AtomicAttempt` claims, including a correctly pinned composite publisher.

`native_composition.ts` directly invokes the inherited pure publication builder,
four-batch operator, protected runtime source/owner ledger, same-owner runtime,
complete supported SQL/KV/alarm reader, private-main current/stop/full65 assessment
and owner stop/close. Its fixed, no-adapter SOURCE harness uses the existing
in-memory SQLite fixtures, whose fetch/socket/DNS paths refuse. Each D1 batch,
native SQL, KV/alarm operation, RPC and the harness's own metering SQL is recorded.
The publication execution is fenced against its independently prepared four exact
SQL/argument batches before each native boundary; one request cannot stand for it.

The fixed native failure cases exercise admitted-before-close completion followed
by stale admission refusal; UPSERT/REPLACE/parent-delete denial; committed close
with lost ACK and no later work; cold malformed control; expired protected header
without payload/native acquisition; both delayed generations; distinct scheduled,
session, authentication/audit and status writes; service/queue/hint/alarm fences;
trusted operator guard bypass; actual mutate/revert with restored end facts but
forbidden committed history; and retained partial output. The selected native
schema contains no CASCADE relationship, so the native case reports that fact;
the separate miniature contains and tests an actual cascade. These native cases
remain SOURCE fixtures, not provider/native qualification or campaign runs.

`native_operator.py` composes the existing publisher's concrete request methods,
including their nested immutable-ID/version/deployment/readback calls. The
prospective restore program permits one separately named exact retained-version
restore after its finite closed preflight; it does not reset or replay the
inherited initial deployment. The original provider files are unchanged. Exact
ordinary closed authentication is exercised through the inherited
`closedRestorationCheck` handler and its real lookup/security response. This local
handler check does not qualify an external HTTPS edge/client transport.

`native_dispatch.executeReviewedNativeProgram(facts, execute=false)` is the
disabled-by-default concrete SDK body. A genuine Root source caller must supply
the typed `ReviewedNativeFacts` carrier, actual SDK/journal references and current
independently reviewed source/packet/cost/holder facts. Constructing that carrier,
choosing its scope, echoing its digests or returning from a callback authenticates
none of those meanings. There is no actual carrier, JSON/environment grant loader
or qualification factory here. The Root assertion and physical-observation
capabilities are explicit external trust premises, required before the SDK call.

The body validates strict inventories, finite clocks, original program/packet/
lease identities and fixed case stage/method order. It uses the inherited named
main/owner/publication/capture/ordinary SDK methods; Python-owned provider methods
have the explicit `InheritedOperatorSDKBindings` piece. A whole bounded subtree
is marked dispatching atomically before an opaque SDK call. A qualified holder's
synchronous fence must match every physical descendant before its effect;
unknown or unobservable RPC internals refuse before invocation. Exact observed
subtrees settle atomically afterwards. Missing/extra/unknown observations, source
drift and post-journal/oracle expiry stop the whole lease without refunds.

Case 7 tests both delayed generations only after exact retained restore and its
readback. Its fixed SOURCE experiment keeps the same native fixture and both
existing SDK references alive while the real inherited Python provider code runs
over its invented transport. It independently checks the model deployment and
complete native SQL/schema/rowids/KV/alarm equality, then invokes generations 1
and 2. No actual version/callback/holder qualification follows from that model.

The native trace measures invented fixture statements, effects and retained JSON
bytes. Actual management/SDK wire framing, committed effects, custody, all-writer

`native_journal.SQLiteNativeBroker` atomically reserves the complete immutable
leaf tree and every counter in an external FULL-synchronous SQLite transaction.
Each `begin` commits the exact next context/leaf/request identity before its
effect; `finish` retains its bounded evidence and actual SOURCE cost. Unknown,
overrun, out-of-order or lost acknowledgments spend the whole tree. Cold restart,
a new key and a changed wrapper cannot continue or release it. Logical retained
artifact charging includes the leaf/cost envelope and the whole lease once;
SQLite physical page writes remain a distinct unqualified implementation detail.

`make_native_lease` binds the full native program but deliberately carries

still refuses first. The bounded `rehearse_durable_operator` source-owned caller
demonstrates the same broker hooks on four real inherited provider operations

model events/body bytes are distinct from unknown actual provider effects and
HTTP framing. The 1,000-plus-leaf native wiring inspection is not admitted as a
256-SQL finite campaign, and none of these helpers raises its limits.

## Source rehearsal

Run the installed independent tests with the repository's pinned uv workflow:

```text
uv run --frozen --no-sync python -m unittest discover -s probes/pmb1-finite-runner -p "test_*.py"
uv run --frozen --no-sync ruff check probes/pmb1-finite-runner
uv run --frozen --no-sync ruff format --check probes/pmb1-finite-runner
uv run --frozen --no-sync pyright probes/pmb1-finite-runner
node_modules/.bin/tsc -p probes/pmb1-finite-runner/tsconfig.json --noEmit
```

Toolchain versions and dependency locks remain unchanged. Frozen source pins
must be verified against an independently retained expected manifest digest;
recomputing a current pin is not independent semantic acceptance.

The portable case-7 SOURCE launcher also needs an explicit `SourceTestTools`
descriptor containing the pinned uv executable and a writable cache directory.
Test runners may instead set `PMB1_SOURCE_TEST_UV` and
`PMB1_SOURCE_TEST_UV_CACHE`. The launcher verifies uv 0.12.5 before its fixed
`run --frozen --no-sync` SOURCE subprocess. It has no ambient-uv fallback,
installation path or actual Root/provider authority. The fixed Root-body yield
rehearsal uses an explicitly invented journal ownership model; the separate
SQLite broker/actual provider-hook tests own external durability evidence.
